# World-clock hierarchy, stable base identity, and broader city sharing

The change expands the city catalogue, promotes the base city into the WorldClock hero, adds explicit ordering controls, and clarifies Automatic theme behavior. Base selection now follows participant identity, while city-page CTAs carry labels for secondary cities sharing an IANA zone. The remaining risks are URL-state data loss and lost base-city management actions. Watch for: **[confirmed]** `~` in a custom label being treated as another participant; **[confirmed]** legacy links losing valid no-slash zones; **[confirmed]** base-city rename/removal becoming indirect; **[confirmed]** no CTA round-trip coverage for same-zone secondary cities.

**Verdict**: NEEDS_CHANGES

## High-level view

**[confirmed]** Filtering the base out of the row list also removes its only rename and remove controls. The identity refactor preserves the base during reorder/removal, but the hero does not replace those management actions.

The new `~` separator avoids collisions with underscores in IANA zones, but `encodeURIComponent` leaves `~` unescaped. **[confirmed]** A label such as `Ops~East` is split on reload or share and returns as `Ops`.

Legacy decoding splits `_` only before a slash-based zone or `UTC`. **[confirmed]** Valid identifiers such as `CST6CDT` do not match, so the participant is absorbed into the preceding chunk and dropped.

City-page scenarios include `city.name`, preserving Chengdu, Kyoto, and similar same-zone cities. **[confirmed]** Tests cover generic labels and search, but do not follow a generated CTA and verify the resulting base identity.

## New participant delimiter collides with editable labels

`SEP_PERSON` is `~`, while labels pass through `encodeURIComponent` before the participant string reaches `URLSearchParams` (`src/lib/time/share.ts:25`, `src/lib/time/share.ts:61`). `encodeURIComponent` leaves `~` unchanged; `URLSearchParams.get` restores every encoded tilde before `raw.split(SEP_PERSON)` (`src/lib/time/share.ts:94-96`). **[confirmed]** The decoder cannot distinguish a delimiter from a user-entered tilde.

```text
Europe/London-540-1020-12345-Ops~East~Asia/Tokyo-540-1020-12345
```

This becomes three chunks: `East` is discarded and the first label returns as `Ops`. The loss appears only after reload, bookmark, or sharing. Preserve an inner escape through `URLSearchParams.get`, or use a length-delimited/base64url/JSON representation.

## Legacy boundary detection excludes valid IANA identifiers

The fallback `_(?=(?:[A-Za-z]+\/|UTC-))` misses valid no-slash identifiers including `CST6CDT`, `EST5EDT`, `MST7MDT`, and `PST8PDT` (`src/lib/time/share.ts:96`). **[confirmed]** `Europe/London-..._CST6CDT-...` remains one chunk, so only London survives.

Because this branch preserves issued links, uncommon zones still require lossless parsing. Validate candidate zone prefixes with `isValidTimeZone` rather than approximating IANA syntax, and assert participant order and anchor resolution in a legacy regression test.

## Hero-only base presentation removes management actions

WorldClock filters `s.anchor.id` before creating `CityRow` (`src/components/WorldClock.tsx:223-240`); rename and remove exist only on those rows, while the hero renders the base label as text (`src/components/WorldClock.tsx:107`). **[confirmed]** The current base cannot be renamed or removed directly.

The workaround is to make another city the base, manage the old base after it reappears, and optionally switch back. Move rename/remove into the hero while keeping removal disabled for a one-participant scenario.

## Same-zone seeds lack a regression assertion

The generated scenario sets `label: city.name` (`src/pages/time/[city].astro:26-33`), which distinguishes Chengdu from Shanghai and Kyoto from Tokyo. **[confirmed]** Unit tests do not construct this seed, and browser smoke opens `/time/chengdu` without following either CTA (`scripts/browser-smoke.mjs:32-35`).

Follow “Add Chengdu to a world clock” and assert that Chengdu is the hero base and absent from secondary rows, or cover the same encode/decode behavior in a focused page-seed test.
